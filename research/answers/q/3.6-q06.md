## Q6. What is spark.shuffle.file.buffer — what is it buffering, and when does increasing it help?

`spark.shuffle.file.buffer` defaults to 32k (KiB). It sizes the in-memory buffer for each shuffle file *output* stream (the buffer a map task writes through before the data hits disk), and larger buffers reduce the number of disk seeks and system calls needed to create the intermediate shuffle files[^spark-configuration]. Learning Spark's tuning table recommends bumping it to 1 MB for large jobs, so Spark does more buffering before writing the final map results to disk[^learning-spark-2e]. It helps when map tasks are I/O-bound writing many shuffle files: fewer, larger writes trade some per-task memory for less disk-seek and syscall overhead during the shuffle-write phase[^learning-spark-2e].
