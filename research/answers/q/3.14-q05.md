## What exactly is taskMetrics.peakExecutionMemory tracking — Tungsten off-heap, on-heap execution pool, or both?

Q5's own retrieved chunks (spark-history-server, spark-monitoring) surface only the **executor**-level `peakMemoryMetrics.OnHeapExecutionMemory` ("Peak on heap execution memory in use, in bytes") and `.OffHeapExecutionMemory` ("Peak off heap execution memory in use, in bytes") gauges[^spark-history-server], not a description of the **task**-level `peakExecutionMemory` accumulator itself. [UNRESOURCED: Spark's monitoring docs do describe `peakExecutionMemory` as "peak memory used by internal data structures created during shuffles, aggregations and joins ... For SQL jobs, this only tracks all unsafe operators and ExternalSort," and the Tungsten/`UnsafeRow`/`sun.misc.Unsafe` background behind "unsafe operators" is accurate — but both passages surfaced under a different question's retrieval, not Q5's own top-k, so neither is citable here.]

`peakExecutionMemory` is a task-level accumulator, distinct from the separate executor-level `peakMemoryMetrics.OnHeapExecutionMemory` / `.OffHeapExecutionMemory` gauges, which report the on-heap and off-heap execution pools as two separate numbers at the executor level rather than as a single per-task figure[^spark-history-server]. Whether the task-level figure itself covers on-heap use, off-heap use, or both isn't resolvable from Q5's own retrieved chunks; that would require the [UNRESOURCED] passage above.
