## What is the canonical definition of a "straggler task" in Spark documentation vs in the research literature? Are they the same concept?

The most direct definition in the retrieved corpus comes from a Spark performance book, not from Spark's own reference docs: "Stragglers are those tasks within a stage that take much longer to execute than the other tasks in that stage." The same source ties stragglers directly to partitioning: they show up when Spark hasn't allocated resources correctly and, in particular, when data isn't partitioned evenly. Skewed keys produce a skewed task-duration distribution, and because stages run in sequence, a straggler in one stage can hold up the whole job[^high-perf-spark].

A second, narrower framing shows up in discussions of task memory management: a straggler is described there as "the last remaining task" in a stage, the one still running after every other task in that stage has finished. That framing matters operationally because Spark's memory manager treats a lone running task differently: with only one active task on an executor, dynamic memory allocation lets it claim the full execution memory pool, which is called out as one advantage of dynamic over static memory assignment for handling stragglers[^spark-notes-task-memory-management].

The two descriptions are the same concept from two angles: a task that is far behind its peers in the same parallel stage, for whatever reason (skew, an overloaded executor, a slow node), and that lag delays the stage's completion. Nothing in the retrieved corpus points to a separate, formally distinct academic definition to contrast against the Spark-community one; the practitioner-book definition already matches the general distributed-systems usage of the term.
