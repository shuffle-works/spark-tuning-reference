## Q2. At what point in query execution are shuffle statistics available to AQE — after all map tasks complete, or incrementally?

Shuffle statistics become available to AQE only once a query stage is fully materialized, not incrementally as individual map tasks finish. A shuffle or broadcast exchange is a "materialization point": the following stage can only proceed once all parallel processes producing that materialization have completed, and this is precisely why materialization points are the reoptimization opportunity: it's the moment when statistics on *all* partitions of a stage are available and the successor stage hasn't started yet[^databricks-aqe]. AQE's loop kicks off all leaf stages (the ones with no upstream dependency) first; as each one finishes materializing in full, the framework marks it complete, updates the plan with the collected runtime statistics, and re-optimizes before launching the next stages whose children are now all materialized[^databricks-aqe]. So the granularity is per-stage (i.e., after all map tasks belonging to that shuffle write have completed), not per-task.
