## Q3. What is the difference between Parquet row group size and HDFS/S3 block size, and how do they interact for task parallelism?

Row group size is a Parquet-internal unit: the amount of data (across all columns) grouped together with its own set of column chunks. The spec recommends large row groups (512MB–1GB) because "larger row groups allow for larger column chunks which makes it possible to do larger sequential IO," at the cost of more write-path buffering[^parquet-format-spec-3]. Block size is a property of the underlying filesystem (HDFS `dfs.blocksize`, or the analogous object-size chunking on S3). The Parquet spec explicitly calls out the interaction: "since an entire row group might need to be read, we want it to completely fit on one HDFS block. Therefore, HDFS block sizes should also be set to be larger," recommending as an optimized setup "1GB row groups, 1GB HDFS block size, 1 HDFS block per HDFS file"[^parquet-format-spec-3].

For task parallelism, Spark's file-based readers inspect the file's footer/row groups and slice the file accordingly: "for structured formats like Parquet, ORC, or Avro, Spark actually reads the metadata (footers, row groups, that kind of thing) and tries to slice the file in a way that makes sense. Often you'll see one partition per row group, though Spark may merge or split depending on file sizes and configs"[^luminousmen-partitions]. A concrete example given: a single 30GB Parquet file with 300 row groups is split by Spark into exactly 300 partitions[^luminousmen-partitions]. If a row group is not aligned to fit inside one block (i.e., row group size exceeds block size, or block boundaries fall mid-row-group), the row group cannot be read from a single block, undercutting the locality benefit the spec's alignment recommendation is meant to preserve[^parquet-format-spec-3]. On the Spark-configuration side, `spark.sql.files.maxPartitionBytes` (128MB by default) and the related `spark.sql.files.maxPartitionNum`/`minPartitionNum` settings govern how many split-file partitions Spark targets for file-based sources generally[^spark-sql-perf-tuning-1], while for row-group-oriented sources like Parquet the row-group boundaries are the dominant factor in how many partitions a single file yields[^luminousmen-partitions].
