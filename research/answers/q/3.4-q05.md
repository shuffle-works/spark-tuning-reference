## What is the partition sizing rule of thumb (128–256 MB per task) — where does this number come from, and does it refer to input bytes, output bytes, or compressed bytes?

The clearest byte-based default in the retrieved material is `spark.sql.files.maxPartitionBytes`, which defaults to 128 MB and governs the target chunk size when Spark splits splittable file-based sources (CSV, JSON, line-delimited text) into input partitions, based on file size[^luminousmen-partitions]. [NEEDS-REVIEW: whether that threshold is measured against compressed on-disk bytes versus deserialized in-memory bytes isn't addressed by the retrieved sources — luminousmen-partitions and the Spark source config doc both describe the setting only in terms of file size / bytes packed per partition, without distinguishing compressed from deserialized bytes.]

Cloudera's tuning guide approaches sizing from the shuffle side instead of the input side: since in-memory shuffle size is hard to measure directly, it recommends estimating it from the ratio between a stage's Shuffle Spill (Memory) and Shuffle Spill (Disk) metrics rather than assuming a fixed byte constant[^cloudera-tuning-spark].
