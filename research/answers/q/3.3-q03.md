## Does storage memory ever evict execution memory, or is eviction unidirectional (storage to execution)?

Eviction is one-directional: execution can evict storage, but storage can never evict execution. As luminousmen-memory-management puts it: "If Execution needs memory, it takes it. If Storage is using that space (cached RDDs, broadcasts), Spark starts evicting blocks. If Execution is idle, Storage can grow into that space, until Execution comes back."[^luminousmen-memory-management] That growth-then-shrink-back behavior is dynamic borrowing, not storage evicting execution. As spark-notes-task-memory-management summarizes the agreement between the two regions: "keep acquiring execution memory and evict storage as you need more execution memory"[^spark-notes-task-memory-management], never the reverse. The same asymmetric rule carries over when off-heap memory is enabled (`spark.memory.offHeap.enabled=true`): execution still has priority and storage still gets evicted first[^luminousmen-memory-management].
