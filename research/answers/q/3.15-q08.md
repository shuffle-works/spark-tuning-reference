## Q8. What is the default and behavior of spark.sql.adaptive.coalescePartitions.minPartitionSize (introduced Spark 3.2+)? How does it interact with advisoryPartitionSizeInBytes?

`spark.sql.adaptive.coalescePartitions.minPartitionSize` defaults to 1MB, introduced in 3.2.0, and is validated in the Spark source as a `bytesConf` with `checkValue(_ > 0, "minPartitionSize must be positive")`[^spark-source-sql-conf]. Its documented purpose: "The minimum size of shuffle partitions after coalescing. This is useful when the target size is ignored during partition coalescing, which is the default case"[^spark-sql-perf-tuning].

That "default case" is `spark.sql.adaptive.coalescePartitions.parallelismFirst=true` (default since 3.2.0): when true, Spark ignores the `advisoryPartitionSizeInBytes` target (default 64MB) when coalescing contiguous shuffle partitions and instead computes a (usually smaller) target size from the cluster's default parallelism[^spark-configuration][^spark-sql-perf-tuning]. In that mode `minPartitionSize` is the only thing still enforced: a floor so parallelism-driven coalescing doesn't produce tiny partitions. Set `parallelismFirst` to false and coalescing goes back to targeting `advisoryPartitionSizeInBytes` directly[^spark-sql-perf-tuning][^spark-source-sql-conf]. High Performance Spark notes a related but distinct knob for minimum parallelism after coalescing, `spark.sql.adaptive.coalescePartitions.minPartitionNum`, useful when the advisory size default is a poor fit for data that is slow to compute despite being small[^high-perf-spark].
