## Q10. How do `spark.dynamicAllocation.minExecutors` and `spark.dynamicAllocation.maxExecutors` behave when min is greater than max (inverted), and when maxExecutors is left unset (unbounded)?

By default, `spark.dynamicAllocation.minExecutors` is `0` and `spark.dynamicAllocation.maxExecutors` is `infinity`[^spark-configuration]. So if `maxExecutors` is left unset, dynamic allocation is effectively unbounded on the high end, limited in practice only by cluster capacity or scheduler quotas outside Spark itself. `spark.dynamicAllocation.initialExecutors` defaults to whatever `minExecutors` is set to, though if `--num-executors` (or `spark.executor.instances`) is set to a larger value, that larger value is used as the initial executor count instead[^spark-configuration]. The `executorAllocationRatio` setting also confirms that whatever target executor count dynamic allocation computes to maximize parallelism, that target can still be overridden (clamped) by the `minExecutors` and `maxExecutors` settings[^spark-configuration]. Both bounds act as hard floor/ceiling clamps around the ratio-driven target.
