## Q5. What statistics does ORC collect (min/max, bloom filters, row index stride)? How does ORC's predicate pushdown differ from Parquet's?

ORC's `ColumnStatistics` protobuf message records, per column, the row count and, "for most of the primitive types, ... the minimum and maximum values; and for numeric types it additionally stores the sum. From Hive 1.1.0 onwards, the column statistics will also record if there are any null values within the row group by setting the `hasNull` flag. The `hasNull` flag is used by ORC's predicate pushdown to better answer 'IS NULL' queries"[^orc-spec-1]. These statistics exist at two granularities: a `RowIndexEntry` per row group (row groups default to 10,000 rows) giving stream positions plus statistics for that row group, with the index streams "placed at the front of the stripe, because in the default case of streaming they do not need to be read. They are only loaded when either predicate push down is being used or the reader seeks to a particular row"[^orc-spec-2]; and file-level `StripeStatistics`, which "enable input split elimination based on the predicate push-down evaluated per a stripe"[^orc-spec-3].

ORC also supports Bloom filters, added "from Hive 1.2.0 onwards": a `BLOOM_FILTER` stream is recorded per row group for any column named in the `orc.bloom.filter.columns` table property, and "only the row groups that satisfy min/max row index evaluation will be evaluated against the bloom filter index"[^orc-spec-2]: ORC's Bloom filter check is a second-stage filter applied only after the min/max row-index check has already passed, rather than an independent check. In Spark, ORC predicate pushdown is controlled by `spark.sql.orc.filterPushdown` (default `true`, since 1.4.0)[^spark-configuration-2].

The high-level difference, echoing Q1: "for the most part, they're quite similar; the fundamental difference is that Parquet is further optimized for use with Spark, whereas ORC is further optimized for Hive"[^definitive-guide-2]. The two-stage min/max-then-Bloom-filter evaluation order documented for ORC[^orc-spec-2] is the one concrete sequencing difference in the retrieved material; Parquet's own Bloom filters and ColumnIndex are documented as independent pruning mechanisms, without that same two-stage ordering specified in the retrieved Parquet chunks[^parquet-bloom-filters].
