## When using repartition(col) for join alignment, does Spark guarantee that both DataFrames will use the same partitioner if the same column and count are specified?

No, and the reason is architectural rather than a tuning nuance. High Performance Spark is explicit that `repartition` and `coalesce` "do not assign a known partitioner" to the resulting RDD, in contrast to `partitionBy`, which does[^high-perf-spark]. A "known partitioner" matters because Spark's join planner only skips a shuffle when both sides already carry partitioner objects it can prove equal: for a `HashPartitioner` that means equal partition counts, for a `RangePartitioner` it means equal range bounds[^high-perf-spark]. Since `repartition(n, col)` doesn't leave that trackable partitioner object behind, calling it with the same column and count on two separate DataFrames produces data that's plausibly laid out the same way, but the planner has no recorded partitioner to compare. It has no basis for treating the two as co-partitioned and skipping the shuffle at join time[^high-perf-spark].

The default join execution path makes the same point from the other side: Spark's shuffle hash join partitions the second dataset using the same partitioner as the first specifically so that matching keys land together, which only implies the shuffle can be skipped when a shared, recognized partitioner is already in place beforehand[^high-perf-spark].

The mechanism that does deliver this guarantee is a different one: storage-partitioned joins, where both tables are physically bucketed identically at the catalog level (for example, Iceberg tables created with matching `PARTITIONED BY (bucket(...))` clauses). When Spark recognizes both sides report the same partitioning through `SupportsReportPartitioning`, it can drop the Exchange (shuffle) node entirely, or shuffle only one side. Plain DataFrame-level `repartition(col)` doesn't offer that guarantee, because it isn't backed by catalog-level partitioning metadata[^spark-sql-perf-tuning][^spark-configuration].
