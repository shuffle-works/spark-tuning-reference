## What is the default number of partitions after a shuffle, and what is the guidance for tuning it?

`spark.sql.shuffle.partitions` defaults to 200[^spark-configuration][^learning-spark-2e], applied to every `join()`, `groupBy()`, and aggregation regardless of how much data is actually moving[^spark-configuration]. Learning Spark 2nd Edition notes that this default is usually too high for small or streaming workloads, where you should pull it down toward the executor core count[^learning-spark-2e]. Past that, the tuning guidance stays informal: there's "no magic formula" for the right number. It depends on data set size, core count, and executor memory, and comes down to trial and error[^learning-spark-2e].

Cloudera's tuning guide argues the same from the opposite direction. Because Spark, unlike MapReduce, has low per-task startup overhead, it's safer to over-provision partitions than under-provision them: "when in doubt, it's almost always better to err on the side of a larger number of tasks"[^cloudera-tuning-spark]. Its heuristic for sizing shuffle partitions is to take a stage that already ran, compute the ratio between its Shuffle Spill (Memory) and Shuffle Spill (Disk) metrics, multiply total shuffle write by that ratio to estimate in-memory shuffle size, then round the resulting partition count up rather than down[^cloudera-tuning-spark]. luminousmen's partition-tuning piece backs the same bias and adds an operational catch: once a shuffle stage has run, you can't change its output file count after the fact without inserting a stage barrier (writing to temporary storage, or calling `localCheckpoint()`) between the shuffle and the write[^luminousmen-partition-tuning].

One hard ceiling, not a tuning target: Spark's sort-based shuffle manager caps output partitions in serialized mode at `PackedRecordPointer.MAXIMUM_PARTITION_ID + 1`, roughly 16.8 million. The source code calls this "an extreme defensive programming measure" since no real shuffle comes remotely close to it[^spark-source-shuffle-manager].
