## What is the exact default for spark.sql.autoBroadcastJoinThreshold in Spark 3.x? Is it based on compressed or uncompressed table size, and where does Spark measure it (statistics, file size, or plan estimate)?

The default is `10485760` bytes, i.e. 10 MB, unchanged since it was introduced in version 1.1.0 and still the documented default for Spark 3.5[^spark-sql-perf-tuning][^spark-configuration]. Setting it to `-1` disables automatic broadcasting[^spark-sql-perf-tuning].

Spark determines whether a table qualifies by consulting table/plan size statistics rather than re-scanning the data at broadcast time: it uses catalog statistics (collected via `ANALYZE TABLE` or exposed through `DESCRIBE EXTENDED`) and the cost estimates in the optimized plan[^spark-sql-perf-tuning]. When those statistics are missing, `spark.sql.statistics.fallBackToHdfs` (default `false`) controls whether Spark falls back to the on-disk (HDFS) file size to decide if a table is small enough for a broadcast join; for partitioned tables without statistics, Spark instead uses the `spark.sql.defaultSizeInBytes` placeholder[^spark-configuration].

Whether the size compared against the threshold is the compressed on-disk size or the uncompressed in-memory size is not stated in any retrieved chunk.
