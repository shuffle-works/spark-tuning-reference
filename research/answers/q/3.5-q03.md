## When a broadcast hint is specified but the table exceeds the threshold, does Spark obey the hint or fall back to sort-merge?

Spark obeys the hint: when a `BROADCAST` hint is attached to a relation, that relation's broadcast join (broadcast hash join, or broadcast nested loop join if there's no equi-join key) is prioritized "even if the size of table 't1' suggested by the statistics is above the configuration `spark.sql.autoBroadcastJoinThreshold`"[^spark-sql-perf-tuning]. The hint only fails to take effect when the specific strategy structurally cannot support the join type being performed. The documentation is explicit that "there is no guarantee that Spark will choose the join strategy specified in the hint since a specific strategy may not support all join types"[^spark-sql-perf-tuning]. Join hints in Spark SQL are advisory: Spark may still choose a different operator than the one hinted[^high-perf-spark]. This is distinct from disabling the threshold outright: setting `spark.sql.autoBroadcastJoinThreshold` to `-1` forces Spark to always fall back to a shuffle sort-merge join instead[^learning-spark-2e].
