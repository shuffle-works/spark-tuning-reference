## Q3. What is peakExecutionMemory exactly — is it measured per-task or per-executor? Does it include storage memory?

`peakExecutionMemory` is a per-task metric, not a per-executor one. It sits in the Task Metrics table alongside `executorRunTime`, `jvmGCTime`, etc., and is defined as "peak memory used by internal data structures created during shuffles, aggregations and joins," where "the value of this accumulator should be approximately the sum of the peak sizes across all such data structures created in this task"; for SQL jobs it "only tracks all unsafe operators and ExternalSort"[^spark-history-server]. That scope (shuffles, aggregations, joins, unsafe operators, `ExternalSort`) is execution memory, not storage/cache memory. It does not include memory for cached RDDs or broadcast variables, which the same docs track separately under executor-level storage-memory fields (`memoryUsed`, `.usedOnHeapStorageMemory`, etc.)[^spark-history-server]. Those storage-memory and `peakMemoryMetrics.*` fields are executor-level, not task-level, and are reported via the executor heartbeat[^spark-history-server].
