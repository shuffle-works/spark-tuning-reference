## Q10. Parquet v1 vs v2 (parquet.writer.version) — what is the practical difference for Spark readers, and is v2 safe to enable by default?

The Parquet format spec documents Data Page V2 as an explicitly forward-*incompatible* feature: "Data Page V2 headers: a reader that only understands `DataPageHeader` cannot parse `DataPageHeaderV2` pages"[^parquet-format-spec-5]. The spec also notes that the version field in a file's `FileMetadata` "has historically been used inconsistently: writers populate 1 or 2 without a consistent relationship to the features actually used"[^parquet-format-spec-5], meaning the file-level version marker itself is not a fully reliable signal of which page-header format is actually in use.

The practical consequence for Spark readers: enabling `parquet.writer.version=2` changes the on-disk page-header encoding to `DataPageHeaderV2`, which any reader (a different, older Spark version, or a non-Spark engine like Hive/Impala) that only implements the original `DataPageHeader` cannot parse[^parquet-format-spec-5]. This is consistent with the general cross-version compatibility warning given in *Spark: The Definitive Guide*: "even though there are only two options, you can still encounter problems if you're working with incompatible Parquet files. Be careful when you write out Parquet files with different versions of Spark (especially older ones) because this can cause significant headache"[^definitive-guide-5]. So v2 is not something to flip on by default purely for its own benefits (e.g., its more compact encodings) without confirming every downstream reader of that data supports `DataPageHeaderV2`: it is a forward-incompatible, not forward-compatible, format change[^parquet-format-spec-5].
