## Does repartition(n) guarantee exactly n output partitions? What algorithm does it use — does it use a hash shuffle?

Yes. The RDD API docstring is explicit: `repartition(numPartitions)` "return[s] a new RDD that has exactly numPartitions partitions"[^spark-source-rdd]. Under the hood it's just `coalesce(numPartitions, shuffle = true)`[^spark-source-rdd].

The mechanism is a hash shuffle. Spark first spreads records across a temporary key space starting from a randomized position, seeded per-partition via `XORShiftRandom`, so upstream data gets distributed evenly rather than clustered by its original layout[^spark-source-rdd]. That gets fed through a `ShuffledRDD` keyed by a `HashPartitioner(numPartitions)`, then wrapped in a `CoalescedRDD` to land on exactly the requested partition count[^spark-source-rdd]. High Performance Spark puts the same mechanics more plainly: "repartition shuffles the RDD with a hash partitioner and the given number of partitions"[^high-perf-spark]. This holds whether the new count is bigger or smaller than the current one. Repartition always does the full shuffle, unlike coalesce[^definitive-guide].
