## Q7. Where exactly is SparkListenerStageSubmitted emitted in the event log — is it fired when the stage is created or when the first task is launched?

The event log record itself is a straight serialization of a `StageInfo`: `stageSubmittedToJson` writes the "Event" name plus the `stageInfo` and any properties, with no task-level data attached[^spark-source-json-protocol]. That shape is consistent with the event representing the stage as a unit, not an individual task launch. On the scheduling side, the DAGScheduler "doesn't pre-schedule all stages at once. Instead, it reacts to stage completions and unlocks child stages on-the-fly," and "once the DAGScheduler has carved the DAG into stages and handed off a TaskSet for the next stage," control passes to the TaskScheduler, which is the component that actually "assigns tasks to executors"[^luminousmen-anatomy]. Read together, this points to `SparkListenerStageSubmitted` firing when the DAGScheduler creates/submits the stage's `TaskSet`, before the TaskScheduler has placed any individual task on an executor. But the corpus doesn't name the exact DAGScheduler call site (e.g., `submitStage` vs. `submitMissingTasks`), so that precise line is `[UNRESOURCED]`.
